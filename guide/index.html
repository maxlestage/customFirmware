Guide pas à pas

Installer AOSP sur le Nothing Phone (4b), avec le code de l'appareil en Rust

Ce guide décrit, dans l'ordre, tout le chemin entre un Nothing Phone (4b) d'origine et un système AOSP compilé par vous, dont les services propres à l'appareil sont écrits en Rust. Chaque étape dit d'où viennent ses commandes et si elles ont déjà été essayées sur ce téléphone.

  • Sources officiellesLes commandes viennent de la documentation d'AOSP ou de Nothing Archive.
  • À confirmer sur le 4bLa méthode marche sur des appareils proches ; elle n'a pas encore été essayée sur le Phone (4b).
  • À écrire par le projetLe projet doit encore écrire cette partie ; le code montré est un point de départ.

Mis à jour le 26 novembre 2026.

00

Avant de commencer

Sources officielles10 minutes de lecture

Savoir ce que l'on risque et réunir le matériel.

Rien de ce guide n'est réversible sans effort. Lisez-le une fois en entier avant de taper la première commande.

  • Un Nothing Phone (4b), modèle A009P, nom de code SuperContra.
  • Un câble USB-C qui transporte les données, pas seulement la charge.
  • Un ordinateur Linux 64 bits x86, avec au moins 64 Go de mémoire et 400 Go d'espace libre : 250 Go pour les sources d'AOSP, 150 Go pour la compilation.
  • Une connexion rapide : les sources d'AOSP pèsent des dizaines de gigaoctets.
Attention. Déverrouiller le bootloader efface toutes les données du téléphone et peut annuler la garantie. Sur les puces Qualcomm, le niveau de protection Widevine passe de L1 à L3 (vidéo en définition réduite dans certaines applications), et les applications qui vérifient l'intégrité de l'appareil (banques, paiement) peuvent refuser de fonctionner.
Attention. Une erreur d'installation peut rendre le téléphone inutilisable. Gardez toujours de côté le firmware d'origine (étape 03) et ne reverrouillez jamais le bootloader sur un système modifié.

Source : AOSP : configuration requise

02

Relever les informations du téléphone

Sources officielles10 minutes

Noter la version exacte du système et la configuration de l'appareil, avant d'y toucher.

  1. Ouvrez Paramètres → À propos du téléphone et appuyez sept fois sur « Numéro de build » : les options pour les développeurs apparaissent.
  2. Dans Paramètres → Système → Options pour les développeurs, activez « Débogage USB ».
  3. Branchez le téléphone et acceptez la demande d'autorisation qui s'affiche.
Vérifier. getprop.txt contient plusieurs centaines de lignes, et ro.build.display.id donne une version de la forme SuperContra-B4.1-….
Astuce. Copiez le fichier fstab trouvé avec adb pull /vendor/etc/<nom du fichier> . : il décrit les partitions que le système monte au démarrage.

Source : Nothing Archive : activer les options pour les développeurs

03

Sauvegarder le système d'origine

À confirmer sur le 4b30 minutes

Avoir sur l'ordinateur le firmware complet de votre version, pour pouvoir revenir en arrière.

Sauvegardez d'abord vos données personnelles (photos, messages, comptes) : elles seront effacées. Puis téléchargez le firmware d'origine correspondant exactement à la version relevée à l'étape 02.

Nothing ne publie pas d'images d'usine. Le projet communautaire Nothing Archive conserve les mises à jour officielles du Phone (4b), déjà découpées en images : image-boot.7z, image-firmware.7z, image-logical.7z.001, .002… et un fichier d'empreintes -hash.sha256.

Vérifier. Le dossier contient des fichiers .img, dont boot.img, init_boot.img, vendor_boot.img, vbmeta.img et les partitions logiques (system, vendor, product…).
Attention. Ne téléchargez que la version exacte de votre téléphone, ou une plus récente : revenir à une version plus ancienne peut être refusé par le téléphone.

Source : Nothing Archive : firmware du Phone (4b)

Source : payload_dumper (Rust)

04

Déverrouiller le bootloader

À confirmer sur le 4b15 minutes

Autoriser le téléphone à démarrer un système qui n'est pas signé par Nothing.

La procédure ci-dessous est celle de Nothing Archive pour les téléphones Nothing ; aucune source ne mentionne encore le Phone (4b) en particulier. Aucun code de déverrouillage n'est demandé par Nothing pour les modèles documentés.

  1. Dans Paramètres → Système → Options pour les développeurs, activez « Déverrouillage OEM » et « Débogage USB ».
  2. Si l'option « Déverrouillage OEM » est grisée, connectez le téléphone à Internet quelques minutes, puis réessayez.
  1. Sur le téléphone, choisissez l'option de déverrouillage avec les touches de volume, puis confirmez avec le bouton marche.
  2. Le téléphone s'efface et redémarre. Refaites la configuration initiale, réactivez les options pour les développeurs et vérifiez que « Déverrouillage OEM » est toujours activé.
Vérifier. Au démarrage, le téléphone affiche un avertissement « Orange State » : c'est normal, il signale un bootloader déverrouillé.
Attention. Pour revenir en arrière, il faudra d'abord réinstaller le système d'origine complet (étape 11). Reverrouiller (fastboot flashing lock) avec une partition modifiée peut rendre le téléphone inutilisable.

Source : Nothing Archive : déverrouiller le bootloader

05

Extraire les fichiers propriétaires

À confirmer sur le 4b1 à 2 heures

Récupérer, depuis le système d'origine, les binaires de Qualcomm et de Nothing qu'AOSP ne fournit pas.

Le modem, le GPU, la caméra ou le Wi-Fi ont besoin de pilotes fermés, rangés dans les partitions vendor, odm et vendor_dlkm. AOSP ne les a pas : on les reprend tels quels depuis les images de l'étape 03.

La liste des fichiers à reprendre s'écrit dans proprietary-files.txt, à la racine du device tree, un chemin par ligne. Un outil du projet, écrit en Rust, lira cette liste et copiera les fichiers dans vendor/nothing/SuperContra.

Astuce. Les vrais noms de fichiers se lisent dans /mnt/vendor. Les ports LineageOS d'appareils Qualcomm proches, comme celui du Phone (4a), montrent à quoi ressemble une liste complète.

Source : Un port voisin : LineageOS pour le Phone (4a), et ses fichiers propriétaires

06

Télécharger AOSP

Sources officielles1 à 3 heures

Récupérer les sources d'Android sur l'ordinateur.

android-latest-release désigne toujours la dernière version publiée d'Android (Android 17 en novembre 2026). Le système d'origine du 4b est sous Android 16 : la séparation entre système et vendor d'Android (Treble) permet en principe de faire tourner un système plus récent sur les pilotes d'origine.

Vérifier. La commande repo sync se termine sans erreur et ~/aosp contient build/, frameworks/, system/…

Source : AOSP : télécharger les sources

07

Le noyau

À écrire par le projet1 heure pour le noyau d'origine

Démarrer d'abord avec le noyau d'origine, puis le recompiler depuis les sources de Nothing.

Nothing publie les sources du noyau du Phone (4b) (Linux 6.1), mais sans instructions de compilation. Pour le premier démarrage, le plus sûr est de réutiliser le noyau de Nothing, extrait de boot.img : on sait qu'il fonctionne avec les pilotes d'origine.

L'arbre contient les fichiers de Kleaf, le système de compilation par Bazel des noyaux Android, mais pas la commande exacte pour ce téléphone. Trouver cette commande est une tâche du projet.

Source : NothingOSS : sources du noyau du Phone (4b)

Source : AOSP : compiler un noyau

08

Écrire le device tree

À écrire par le projetPlusieurs jours

Décrire le téléphone à AOSP : son processeur, ses partitions, ses fichiers propriétaires.

Le device tree est un dossier de fichiers Make qui dit à AOSP comment construire un système pour cet appareil. Voici le squelette ; chaque valeur marquée « à relever » vient de l'étape 02.

Vérifier. Après source build/envsetup.sh, la commande lunch sans argument liste aosp_SuperContra-aosp_current-userdebug.

Source : AOSP : compiler (lunch et cibles)

09

Écrire le premier service en Rust

À confirmer sur le 4b2 heures

Ajouter au système un service Binder écrit en Rust, la brique de base de tous les HAL du projet.

Un HAL Android est un service qui parle le langage Binder, décrit par une interface AIDL. AOSP sait générer le code Rust d'une interface AIDL : on écrit l'interface, puis le service en Rust. Le code suit l'exemple officiel d'AOSP.

Attention. SELinux bloque par défaut un service inconnu. Le mode permissif ne sert qu'au premier essai : le vrai HAL aura sa politique SELinux, une interface stable et sa déclaration dans le manifeste VINTF.

Source : AOSP : exemple de service AIDL en Rust

Source : AOSP : les backends AIDL

10

Compiler et installer

À confirmer sur le 4b1 à 6 heures de compilation

Construire le système complet et l'installer sur le téléphone.

La documentation d'AOSP compte environ 40 minutes sur une machine de 72 cœurs, et 6 heures sur 6 cœurs. Le résultat est dans out/target/product/SuperContra.

Vérifier. Le téléphone redémarre sur l'animation d'AOSP. Le premier démarrage peut prendre plusieurs minutes.
Astuce. Si le téléphone revient au bootloader ou boucle au démarrage, ne paniquez pas : passez à l'étape 11 pour réinstaller le système d'origine, puis cherchez la cause dans le journal (adb logcat, s'il s'est lancé assez loin).

Source : AOSP : installer une version compilée

11

Revenir au système d'origine

À confirmer sur le 4b20 minutes

Réinstaller Nothing OS à partir des images sauvegardées à l'étape 03.

Nothing Archive fournit un script qui installe toutes les images d'origine dans le bon ordre. Vérifiez sur sa page qu'il prend en charge le Phone (4b) avant de l'utiliser.

  • Effacer les données : oui, pour une installation propre.
  • Installer sur les deux emplacements (A et B) : oui, recommandé.
  • Désactiver le démarrage vérifié (AVB) : non. Répondre oui empêcherait de reverrouiller le bootloader.
Attention. Si le script affiche une erreur, ne redémarrez pas sur le système : redémarrez sur le bootloader et relancez le script.

Source : Nothing Archive : installer le firmware d'origine
